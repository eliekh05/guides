Btrfs Snapshots with Snapper

Btrfs snapshots capture the state of your filesystem at a point in time. Snapper automates snapshot creation and lets you roll back changes — like Time Machine for Linux.

Check If You Are on Btrfs

df -T / | grep btrfs

Fedora, openSUSE, and some Ubuntu installs use Btrfs by default. Arch Linux lets you choose during install.

Install Snapper

sudo apt install snapper -y          # Ubuntu/Debian
sudo dnf install snapper -y          # Fedora/RHEL
sudo pacman -S snapper               # Arch

Create a Snapper Config for Root

sudo snapper -c root create-config /

This creates a config at /etc/snapper/configs/root and a .snapshots subvolume at /.snapshots.

Manual Snapshots

# Create a snapshot before making changes
sudo snapper -c root create --description "before package update"

# List all snapshots
sudo snapper -c root list

# Show what changed between two snapshots
sudo snapper -c root diff 1 2

# Show which files changed
sudo snapper -c root status 1 2

Automatic Snapshots

Enable snapper's systemd timers for automatic hourly, daily, weekly, and monthly snapshots:

sudo systemctl enable --now snapper-timeline.timer
sudo systemctl enable --now snapper-cleanup.timer

Configure retention in /etc/snapper/configs/root:

TIMELINE_LIMIT_HOURLY="5"
TIMELINE_LIMIT_DAILY="7"
TIMELINE_LIMIT_WEEKLY="4"
TIMELINE_LIMIT_MONTHLY="6"
TIMELINE_LIMIT_YEARLY="2"

Snapshot on Every Package Install (Arch)

Install snap-pac to automatically create pre/post snapshots around every pacman transaction:

sudo pacman -S snap-pac

Now every sudo pacman -S package creates a before and after snapshot automatically.

Roll Back to a Snapshot

# Find the snapshot you want to roll back to
sudo snapper -c root list

# Roll back (this sets the snapshot as the new default subvolume)
sudo snapper -c root undochange 1..0

# Or use snapper rollback (openSUSE/Arch with grub-btrfs)
sudo snapper rollback SNAPSHOT_NUMBER
sudo reboot

Browse a Snapshot Without Rolling Back

sudo mount -o subvol=/.snapshots/5/snapshot /dev/sda2 /mnt
ls /mnt/etc    # browse files
sudo umount /mnt

Delete Snapshots

# Delete a single snapshot
sudo snapper -c root delete 3

# Delete a range
sudo snapper -c root delete 3-7

Check Snapshot Disk Usage

sudo btrfs filesystem du -s /.snapshots/*/snapshot | sort -rh | head -10

Snapshots use copy-on-write — they only store the difference from the current state, not a full copy. A snapshot of a 20GB root filesystem might only use 50MB if little has changed.
