anacron — Schedule Tasks on Machines That Are Not Always On

cron assumes the machine runs 24/7. If a cron job is scheduled for 3 AM and the machine is off, the job never runs. anacron solves this — it runs jobs based on how many days have elapsed since they last ran, catching up when the machine turns on.

How anacron Works

anacron checks timestamps stored in /var/spool/anacron/. When the machine boots or when anacron runs, it checks each job — if the required number of days have passed since the last run, it executes the job after a configurable delay.

Install

sudo apt install anacron      # Ubuntu/Debian (often pre-installed)
sudo dnf install cronie-anacron   # Fedora/RHEL
sudo pacman -S cronie         # Arch (includes anacron)

The anacrontab File

sudo nano /etc/anacrontab
# Format: period  delay  job-id  command
# period = days between runs
# delay  = minutes to wait after boot before running
# job-id = unique name for logging

1     5    daily-backup    /usr/local/bin/backup.sh
7     10   weekly-cleanup  /usr/local/bin/cleanup.sh
30    15   monthly-report  /usr/local/bin/report.sh

Field Explanation

FieldMeaning
1Run every 1 day
7Run every 7 days
@monthlyRun once a month
5 (delay)Wait 5 minutes after boot before running
daily-backupJob ID — used for the timestamp file name

Per-User anacron (No Root Required)

mkdir -p ~/.anacron/spool

# Create user anacrontab
nano ~/.anacrontab
MAILTO=""
1   5   daily-job   /home/youruser/scripts/daily.sh
7   10  weekly-job  /home/youruser/scripts/weekly.sh
# Run manually (add to ~/.profile or cron @reboot)
anacron -t ~/.anacrontab -T ~/.anacron/spool -S ~/.anacron/spool
# Add to crontab to run at boot
crontab -e
@reboot anacron -t ~/.anacrontab -T ~/.anacron/spool -S ~/.anacron/spool

Test Without Waiting

# Force run all jobs regardless of timing
sudo anacron -f -n

# Run a specific job immediately
sudo anacron -f -n daily-backup

# Dry run — show what would run without executing
sudo anacron -n -d

Check Last Run Times

ls -la /var/spool/anacron/
cat /var/spool/anacron/daily-backup    # contains the date of last run

anacron vs cron vs systemd timers

Featurecronanacronsystemd timer
Runs on always-on serversYesYesYes
Catches up missed jobsNoYesYes (Persistent=true)
Sub-day schedulingYesNo (days only)Yes
Root requiredNoNo (user mode)No (user units)
Best forServersLaptops/desktopsModern Linux

For laptops and desktops — use anacron or systemd timers with Persistent=true. Both catch up missed jobs. systemd timers are more powerful but more verbose to configure. anacron is simpler for daily/weekly/monthly tasks.
