Linux File System — Directory Structure Explained

Linux has a single directory tree starting at /. Every file and device lives somewhere in this tree. Understanding where things go is essential for administering any Linux system.

Top-Level Directories

DirectoryPurpose
/Root — top of the entire filesystem
/binEssential user binaries (ls, cp, mv, bash). Symlink to /usr/bin on modern systems
/bootBootloader, kernel, initramfs
/devDevice files — disks, terminals, null, random
/etcSystem-wide configuration files
/homeUser home directories (/home/username)
/libShared libraries. Symlink to /usr/lib on modern systems
/mediaMount points for removable media (USB, optical)
/mntTemporary mount points
/optOptional/third-party software installed outside the package manager
/procVirtual filesystem — running processes and kernel info
/rootRoot user's home directory
/runRuntime data since last boot (PIDs, sockets)
/sbinSystem binaries for administration. Symlink to /usr/sbin
/srvData for services (web, FTP)
/sysVirtual filesystem — kernel and hardware info
/tmpTemporary files, cleared on reboot
/usrUser programs, libraries, documentation
/varVariable data — logs, databases, mail, package cache

Important Subdirectories

/etc/
  passwd        # user accounts
  shadow        # password hashes (root only)
  hosts         # hostname to IP mappings
  fstab         # filesystem mount configuration
  crontab       # system cron jobs
  ssh/          # SSH daemon config
  systemd/      # systemd service files
  apt/          # apt package manager config
  nginx/        # nginx web server config

/var/
  log/          # system and application logs
  lib/          # persistent app data (databases, package state)
  cache/        # cached data (package downloads)
  www/          # web server files (traditional)
  run/          # runtime state (symlink to /run)

/usr/
  bin/          # user commands (ls, grep, python3)
  sbin/         # admin commands (useradd, fdisk)
  lib/          # shared libraries
  local/        # locally installed software (not from package manager)
  share/        # architecture-independent data (man pages, icons)
  include/      # C header files

/proc — Process and Kernel Info

# CPU info
cat /proc/cpuinfo

# Memory info
cat /proc/meminfo

# Kernel version
cat /proc/version

# Running processes (each PID is a directory)
ls /proc/ | grep '^[0-9]'

# Info about process 1 (systemd/init)
cat /proc/1/cmdline
cat /proc/1/status

/dev — Device Files

/dev/sda          # first SATA/SCSI disk
/dev/sda1         # first partition of sda
/dev/nvme0n1      # first NVMe disk
/dev/nvme0n1p1    # first partition of NVMe disk
/dev/null         # discard all data written to it
/dev/zero         # produces infinite zeros
/dev/random       # random data from kernel entropy pool
/dev/tty          # current terminal
/dev/stdin        # standard input
/dev/stdout       # standard output

Finding Files

# Find a file by name
find / -name "filename.txt" 2>/dev/null

# Find all config files for a package
dpkg -L nginx    # Debian/Ubuntu
rpm -ql nginx    # Fedora/RHEL

# Find what package owns a file
dpkg -S /usr/bin/python3
rpm -qf /usr/bin/python3

# Find large files
find / -type f -size +100M 2>/dev/null | sort -rh | head -20

Filesystem Types

TypeUse case
ext4Default Linux filesystem, stable, widely supported
BtrfsSnapshots, compression, checksums — Fedora default
XFSHigh performance, good for large files — RHEL default
ZFSEnterprise features, pools, deduplication
tmpfsRAM-based, used for /tmp and /run
vfat/FAT32Boot partition (EFI), USB drives
NTFSWindows drives (read/write on Linux via ntfs-3g)
