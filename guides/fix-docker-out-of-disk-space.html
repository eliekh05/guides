Fix Docker Out of Disk Space

Docker accumulates unused images, stopped containers, dangling volumes, and build cache over time. A server that seemed to have plenty of space fills up silently.

Check What Docker Is Using

docker system df

This shows a breakdown:

  • Images — all pulled and built images
  • Containers — including stopped containers
  • Volumes — named volumes
  • Build cache — cached build layers from docker build

Safe Cleanup — Remove Only Unused Resources

# Remove stopped containers, unused networks, dangling images, build cache
# Does NOT remove volumes by default
docker system prune

# Same but also remove all unused images (not just dangling ones)
docker system prune -a

# Check what would be removed first (dry run)
docker system prune -a --filter "until=24h"

Remove Specific Resource Types

# Remove all stopped containers
docker container prune

# Remove all unused images
docker image prune -a

# Remove unused volumes (careful — data inside is deleted permanently)
docker volume prune

# Remove unused networks
docker network prune

# Remove build cache
docker buildx prune -a

Remove Everything (Nuclear Option)

# Stop all running containers first
docker stop $(docker ps -q)

# Remove ALL containers, images, volumes, networks
docker system prune -a --volumes

This deletes all data in volumes including databases. Only run this on a development machine or if you are sure nothing important is stored in Docker volumes.

Find Which Images Are Largest

docker images --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}" | sort -k3 -h -r | head -20

Find Large Volumes

docker system df -v | grep -A 100 "VOLUME NAME"

Automate Cleanup with a Cron Job

crontab -e
# Add — runs cleanup every Sunday at 3am
0 3 * * 0 docker system prune -af --filter "until=168h" >> /var/log/docker-cleanup.log 2>&1

The --filter "until=168h" only removes resources unused for more than 7 days — safer than removing everything.

Change Docker Data Directory

If Docker's data directory (default /var/lib/docker) is on a small partition, move it to a larger disk:

sudo systemctl stop docker

sudo nano /etc/docker/daemon.json
{
  "data-root": "/mnt/large-disk/docker"
}
# Copy existing data
sudo rsync -aP /var/lib/docker/ /mnt/large-disk/docker/

sudo systemctl start docker
docker info | grep "Docker Root Dir"

Log Files Eating Space

Container logs grow indefinitely by default. Set a log limit:

sudo nano /etc/docker/daemon.json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
sudo systemctl restart docker

This applies to new containers. For existing containers, recreate them with the new log config.
