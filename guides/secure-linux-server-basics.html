Secure a Linux Server — Essential First Steps

Every new Linux server exposed to the internet needs these steps before anything else. A default install is not secure.

Create a Non-Root User

# Create user
adduser youruser

# Add to sudo group
usermod -aG sudo youruser      # Debian/Ubuntu
usermod -aG wheel youruser     # Fedora/RHEL/Arch

# Switch to new user and verify sudo works
su - youruser
sudo whoami    # should output: root

Set Up SSH Key Authentication

# On your local machine — generate a key if you don't have one
ssh-keygen -t ed25519 -C "your-server"

# Copy public key to server
ssh-copy-id youruser@server-ip

# Or manually:
cat ~/.ssh/id_ed25519.pub | ssh youruser@server-ip "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"

# Test key login before disabling passwords
ssh youruser@server-ip

Disable Password Authentication

sudo nano /etc/ssh/sshd_config
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
AuthorizedKeysFile .ssh/authorized_keys
sudo systemctl restart sshd

# Test from a new terminal BEFORE closing current session
ssh youruser@server-ip

Always test in a new terminal window before closing your current SSH session. A mistake here can lock you out permanently.

Configure the Firewall

# UFW (Ubuntu/Debian)
sudo apt install ufw -y
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status verbose

# firewalld (Fedora/RHEL)
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload
sudo firewall-cmd --list-all

Install and Configure fail2ban

fail2ban bans IPs that fail authentication repeatedly — stops brute force attacks.

sudo apt install fail2ban -y    # Ubuntu/Debian
sudo dnf install fail2ban -y    # Fedora/RHEL

sudo nano /etc/fail2ban/jail.local
[DEFAULT]
bantime  = 1h
findtime  = 10m
maxretry = 5

[sshd]
enabled = true
port = ssh
logpath = %(sshd_log)s
backend = %(sshd_backend)s
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd

Keep the System Updated

# Ubuntu/Debian — enable automatic security updates
sudo apt install unattended-upgrades -y
sudo dpkg-reconfigure -plow unattended-upgrades

# Check what would be upgraded
sudo unattended-upgrade --dry-run --debug

# Manual update
sudo apt update && sudo apt upgrade -y

Change the SSH Port (Optional)

Changing from 22 to a non-standard port reduces noise in logs but is not real security — treat it as log cleanup, not protection.

sudo nano /etc/ssh/sshd_config
# Change: Port 22
# To:     Port 2222

# Allow the new port through firewall first
sudo ufw allow 2222/tcp
sudo ufw delete allow ssh
sudo systemctl restart sshd

# Connect with:
ssh -p 2222 youruser@server-ip

Disable Unused Services

# List all running services
systemctl list-units --type=service --state=running

# Disable services you don't need
sudo systemctl disable --now avahi-daemon
sudo systemctl disable --now cups

Check for Open Ports

# See what is listening
sudo ss -tlnp
sudo netstat -tlnp

# Scan from outside (on your local machine)
nmap -sV server-ip

Set Up Automatic Reboot for Kernel Updates

# Install needrestart
sudo apt install needrestart -y

# Check if a reboot is needed
needrestart -r a
