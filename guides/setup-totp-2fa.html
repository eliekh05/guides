Set Up Two-Factor Authentication (TOTP)

Two-factor authentication (2FA) means even if someone gets your password, they still can't log in without your second factor. TOTP (Time-based One-Time Password) is the most common form — the 6-digit code that changes every 30 seconds in an authenticator app.

How TOTP Works

When you set up 2FA, the site gives you a secret key (usually as a QR code). Your authenticator app and the server both use this secret plus the current time to generate the same 6-digit code. The code changes every 30 seconds and is only valid once. An attacker who intercepts your code can't reuse it.

Enable TOTP on a Service

  1. Go to the service's security settings (usually under Account → Security → Two-factor authentication)
  2. Choose "Authenticator app" or "TOTP"
  3. Open your authenticator app and scan the QR code — or enter the secret key manually if QR doesn't work
  4. Enter the 6-digit code from the app to verify it's working
  5. Save the backup/recovery codes somewhere secure — a password manager, or printed and locked away

Backup Codes — Do Not Skip This

Every service gives you backup codes when you set up 2FA. These are single-use codes that let you log in if you lose your phone. Store them:

  • In your password manager (most reliable)
  • Printed and stored physically somewhere safe
  • In an encrypted file in cloud storage

Do not store them in the same place as your passwords. If you lose your phone and your backup codes, you may be permanently locked out.

Add 2FA to SSH (Linux Servers)

# Install Google Authenticator PAM module
sudo apt install libpam-google-authenticator -y

# Run setup as your user (not root)
google-authenticator

# Answer yes to all prompts
# Scan the QR code with your app
# Save the emergency codes
# Configure PAM to use it
sudo nano /etc/pam.d/sshd
# Add at the top:
auth required pam_google_authenticator.so
# Configure SSH to request both password AND TOTP
sudo nano /etc/ssh/sshd_config
ChallengeResponseAuthentication yes
AuthenticationMethods publickey,keyboard-interactive    # key + TOTP
# or for password + TOTP:
# AuthenticationMethods keyboard-interactive
sudo systemctl restart sshd

Hardware Keys (FIDO2/WebAuthn)

Hardware security keys like YubiKey are stronger than TOTP — they use public-key cryptography and are phishing-resistant (they verify the domain, so a fake login page doesn't work).

  • YubiKey 5 — most compatible, works with FIDO2, U2F, PIV, OTP
  • Google Titan Key — cheaper, FIDO2/U2F only
  • Nitrokey — open source hardware

Setup varies per service but follows the same pattern: Security Settings → Add security key → tap the key when prompted. Register at least two keys — one as a backup.

TOTP from the Command Line

# Generate TOTP codes without an app (useful for scripts)
sudo apt install oathtool -y

# Generate a code from your secret
oathtool --totp --base32 "YOUR_SECRET_KEY"

# Continuous output
watch -n 1 'oathtool --totp --base32 "YOUR_SECRET_KEY"'

What 2FA Does Not Protect Against

  • Real-time phishing — an attacker's fake site forwards your credentials and TOTP code to the real site immediately. Hardware keys (WebAuthn) prevent this.
  • Malware on your device — if your device is compromised, 2FA doesn't help much
  • SIM swapping — SMS 2FA is vulnerable to this. Use TOTP or hardware keys instead of SMS.

Avoid SMS-based 2FA wherever possible. SMS is better than nothing, but TOTP and hardware keys are significantly more secure.
