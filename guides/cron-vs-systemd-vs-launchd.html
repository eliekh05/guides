cron vs systemd Timers vs launchd — Which to Use

Three different task scheduling systems across Linux and macOS. Here is when to use each and how they compare.

Syntax Comparison

cron — Run every day at 3 AM

0 3 * * * /usr/local/bin/backup.sh

systemd timer — Run every day at 3 AM

# backup.timer
[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true

# backup.service
[Service]
ExecStart=/usr/local/bin/backup.sh

launchd — Run every day at 3 AM

<key>StartCalendarInterval</key>
<dict>
  <key>Hour</key><integer>3</integer>
  <key>Minute</key><integer>0</integer>
</dict>

When cron Is Still the Right Choice

  • Simple, well-understood syntax everyone knows
  • Shared hosting or environments without systemd
  • Scripts that run on both Linux and macOS
  • Quick one-liner jobs that do not need logging infrastructure
  • Teams where everyone knows cron and nobody knows systemd timer syntax

When systemd Timers Win

  • The job absolutely must not be missed if the machine was off — Persistent=true
  • The job should only run after another service is ready
  • You want automatic logging via journalctl
  • You need to limit CPU or memory for the scheduled task
  • You want to manage the task with systemctl alongside other services

When launchd Is the Only Option

On macOS, launchd is the correct tool. cron technically works but Apple deprecated it. launchd handles macOS sleep/wake correctly, integrates with Keychain for passwords, and is the official supported method. Use launchd for everything on macOS.

Migration — cron to systemd timer

# Old cron job:
# 0 3 * * * /usr/local/bin/backup.sh

# Equivalent systemd timer:
# /etc/systemd/system/backup.service
[Unit]
Description=Backup Script
[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh

# /etc/systemd/system/backup.timer
[Unit]
Description=Run backup daily at 3 AM
[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true
[Install]
WantedBy=timers.target
sudo systemctl daemon-reload
sudo systemctl enable --now backup.timer
sudo systemctl disable cron   # optionally disable cron if fully migrated
