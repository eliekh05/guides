Fix High CPU Usage on Linux

CPU usage spikes are normal — the problem is when something is pegging the CPU and not letting go. Here's how to find what's doing it and stop it.

Find What's Using the CPU

# Interactive view — updates every 2 seconds
top

# Better version with color and easier controls
htop    # install: sudo apt install htop

# Sort by CPU (already default in top/htop)
# In top: press P to sort by CPU
# In htop: press F6 → CPU%
# One-shot snapshot sorted by CPU
ps aux --sort=-%cpu | head -15

Reading top Output

%CPU column — CPU percentage this process is using
PID        — process ID (needed to kill it)
USER       — who is running it
COMMAND    — the program name

A process using 100% CPU on a quad-core machine is maxing out one core. That's normal for some tasks (video encoding, compiling). It's a problem if it's something that should be idle.

Identify the Process

# Get the full command, not just the truncated name
ps -p PID -o pid,pcpu,pmem,cmd

# See what files it has open
lsof -p PID

# See what network connections it has
ss -tp | grep PID

Common Causes

ProcessLikely cause
kswapd0Out of RAM — Linux swapping heavily. Add RAM or find the memory hog
kworkerKernel worker thread — could be a hardware issue or driver bug
compilerc / cc1 / ldSomething is compiling — normal, just wait
python / node / phpA script is in an infinite loop or doing heavy work
mysqld / postgresA slow query running. Check the DB slow query log
rcu_schedKernel RCU — usually a sign of an overloaded system

Kill a Runaway Process

# Graceful kill (lets process clean up)
kill PID

# Force kill (immediate)
kill -9 PID

# Kill by name
pkill processname
pkill -9 processname

Throttle a Process Instead of Killing It

# Lower priority so it uses less CPU
renice +19 -p PID    # very low priority
renice +10 -p PID    # moderately lower priority

# Limit CPU usage with cpulimit (install first)
sudo apt install cpulimit
cpulimit -p PID -l 25    # cap at 25% CPU

Find CPU Hogs from the Last Hour

# Check system activity (if sysstat is installed)
sudo apt install sysstat
sar -u 1 10    # CPU usage every 1 second, 10 times

# Check for cron jobs that ran recently
grep CRON /var/log/syslog | tail -20

Check for Crypto Mining (Servers)

If your VPS suddenly pegs the CPU and you didn't cause it, check for mining malware:

# Look for processes with high CPU owned by unexpected users
ps aux --sort=-%cpu | head -10

# Check for unusual network connections
ss -tulnp

# Check recently modified files in /tmp
find /tmp -newer /tmp -type f 2>/dev/null

# Check crontabs for all users
for user in $(cut -f1 -d: /etc/passwd); do
  sudo crontab -u $user -l 2>/dev/null && echo "--- $user ---"
done

Persistent High CPU — Check Logs

# System journal
sudo journalctl -p err -b    # errors since last boot

# dmesg for kernel errors
dmesg | grep -i error | tail -20
