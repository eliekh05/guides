Linux Cron Jobs — Schedule Tasks the Right Way

Cron runs commands on a schedule — backups, cleanup scripts, reports, anything that needs to happen automatically. It's been on every Unix system for decades and works exactly the same everywhere.

Edit Your Crontab

crontab -e    # edit your user's cron jobs
crontab -l    # list current cron jobs
crontab -r    # delete all cron jobs (careful)

Cron Syntax

# ┌─ minute (0-59)
# │ ┌─ hour (0-23)
# │ │ ┌─ day of month (1-31)
# │ │ │ ┌─ month (1-12)
# │ │ │ │ ┌─ day of week (0-7, 0 and 7 are Sunday)
# │ │ │ │ │
# * * * * *  command to run

Common Examples

# Every minute
* * * * * /path/to/script.sh

# Every hour at minute 0
0 * * * * /path/to/script.sh

# Every day at 2:30am
30 2 * * * /path/to/script.sh

# Every Monday at 9am
0 9 * * 1 /path/to/script.sh

# Every 15 minutes
*/15 * * * * /path/to/script.sh

# First day of every month at midnight
0 0 1 * * /path/to/script.sh

# Weekdays at 8am
0 8 * * 1-5 /path/to/script.sh

# Multiple times — 9am and 5pm daily
0 9,17 * * * /path/to/script.sh

Shorthand Schedules

@reboot     # once at startup
@hourly     # = 0 * * * *
@daily      # = 0 0 * * *
@weekly     # = 0 0 * * 0
@monthly    # = 0 0 1 * *
@yearly     # = 0 0 1 1 *

Capture Output and Errors

# By default, cron emails output to the local user
# Redirect to a log file instead:
30 2 * * * /path/to/script.sh >> /var/log/myscript.log 2>&1

# Discard all output
30 2 * * * /path/to/script.sh > /dev/null 2>&1

Things That Catch People Out

Use full paths everywhere. Cron doesn't load your shell's PATH. python3 won't work — use /usr/bin/python3. Find the path with which python3.

Scripts must be executable. Run chmod +x /path/to/script.sh first.

No interactive shell. Cron jobs can't prompt for input or read from a terminal.

Environment is minimal. If your script needs environment variables, set them at the top of the crontab or source your profile inside the script.

# Set environment variables in crontab
SHELL=/bin/bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
HOME=/home/youruser

30 2 * * * /path/to/script.sh

System-Wide Cron Jobs

# System crontab (has an extra user field)
sudo nano /etc/crontab

# 30 2 * * * root /path/to/script.sh
#             ^^^^ user to run as

# Drop scripts into these directories instead:
/etc/cron.hourly/
/etc/cron.daily/
/etc/cron.weekly/
/etc/cron.monthly/

Check If Cron Ran

# Check cron logs
grep CRON /var/log/syslog | tail -20       # Debian/Ubuntu
sudo journalctl -u cron | tail -20          # systemd systems
sudo grep CRON /var/log/cron | tail -20     # RHEL/Fedora

Test a Cron Job Without Waiting

# Run the exact command cron would run, as your user
env -i HOME=$HOME /bin/bash -c '/path/to/script.sh'

# This simulates cron's minimal environment
