Let's Encrypt — Free SSL Certificates with Certbot

Let's Encrypt issues free, trusted SSL/TLS certificates. Certbot is the official tool that automates getting and renewing them. This guide covers Nginx and Apache on Ubuntu/Debian.

Install Certbot

# Ubuntu/Debian with Nginx
sudo apt install certbot python3-certbot-nginx -y

# Ubuntu/Debian with Apache
sudo apt install certbot python3-certbot-apache -y

# Fedora/RHEL with Nginx
sudo dnf install certbot python3-certbot-nginx -y

Get a Certificate — Nginx

# Certbot reads your Nginx config and handles everything
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com

# Follow the prompts:
# - Enter an email address for renewal reminders
# - Agree to terms of service
# - Choose whether to redirect HTTP to HTTPS (choose yes)

Get a Certificate — Apache

sudo certbot --apache -d yourdomain.com -d www.yourdomain.com

Get a Certificate — Standalone

If you are not using Nginx or Apache, or want to handle configuration yourself:

# Temporarily stops any web server on port 80
sudo certbot certonly --standalone -d yourdomain.com

# Certificate files will be at:
# /etc/letsencrypt/live/yourdomain.com/fullchain.pem
# /etc/letsencrypt/live/yourdomain.com/privkey.pem

Where Certificates Are Stored

/etc/letsencrypt/live/yourdomain.com/
  fullchain.pem   # certificate + intermediate chain (use this in Nginx/Apache)
  privkey.pem     # private key
  cert.pem        # certificate only
  chain.pem       # intermediate chain only

Test Renewal

# Dry run — checks everything without actually renewing
sudo certbot renew --dry-run

Auto-Renewal

Certbot installs a systemd timer or cron job automatically. Verify it is active:

# Check the systemd timer
sudo systemctl status certbot.timer

# Or check cron
sudo crontab -l | grep certbot

# Test automatic renewal
sudo certbot renew --dry-run

Certificates expire after 90 days. Certbot renews them automatically when they are within 30 days of expiry.

Nginx Config After Certbot

Certbot modifies your Nginx config automatically. The result looks like this:

server {
    listen 443 ssl;
    server_name yourdomain.com www.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;

    location / {
        proxy_pass http://localhost:3000;
    }
}

server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    return 301 https://$host$request_uri;
}

Wildcard Certificates

Wildcard certificates cover all subdomains (*.yourdomain.com) and require DNS validation:

sudo certbot certonly --manual --preferred-challenges dns \
  -d yourdomain.com -d *.yourdomain.com

Certbot will ask you to create a TXT DNS record to prove domain ownership. Add it at your DNS provider, wait a minute, then press Enter to continue.

Revoke a Certificate

sudo certbot revoke --cert-path /etc/letsencrypt/live/yourdomain.com/cert.pem
sudo certbot delete --cert-name yourdomain.com

Troubleshooting

# Port 80 must be open for HTTP challenge
sudo ufw allow 80

# Check Certbot logs
sudo cat /var/log/letsencrypt/letsencrypt.log

# List all certificates
sudo certbot certificates
