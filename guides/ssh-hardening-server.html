SSH Hardening — Lock Down Your Server

A default SSH setup is fine for a home server. A public-facing server is a different story — bots start probing port 22 within minutes of going online. These steps cut the attack surface significantly.

Before You Start

Always keep your current SSH session open while making changes. Test your new config in a second terminal before closing the first one — a mistake could lock you out.

1. Use SSH Keys, Disable Password Login

# First — make sure your SSH key is on the server
ssh-copy-id user@yourserver
# or manually add your public key to ~/.ssh/authorized_keys

# Test that key login works BEFORE disabling passwords
ssh user@yourserver    # should log in without a password prompt
sudo nano /etc/ssh/sshd_config
PasswordAuthentication no
PubkeyAuthentication yes
AuthorizedKeysFile .ssh/authorized_keys
sudo systemctl restart sshd

2. Disable Root Login

# In /etc/ssh/sshd_config
PermitRootLogin no

Log in as a regular user and use sudo for root tasks. Direct root SSH login is unnecessary and risky.

3. Change the Default Port

Not real security — but it eliminates 99% of automated scanning noise:

# In /etc/ssh/sshd_config
Port 2222    # pick anything from 1024-65535

# Open the new port in your firewall first
sudo ufw allow 2222/tcp
sudo ufw delete allow 22/tcp    # after confirming new port works
# Connect with non-default port
ssh -p 2222 user@yourserver

4. Limit Login Attempts

# In /etc/ssh/sshd_config
MaxAuthTries 3
MaxSessions 5
LoginGraceTime 20

5. Restrict Which Users Can Log In

# Only allow specific users
AllowUsers alice bob

# Only allow users in a specific group
AllowGroups sshusers

6. Disable Unused Features

# In /etc/ssh/sshd_config
X11Forwarding no
AllowTcpForwarding no    # unless you need SSH tunneling
PermitEmptyPasswords no
PermitUserEnvironment no

7. Use Fail2ban

Fail2ban watches for repeated failed logins and temporarily bans the IP:

sudo apt install fail2ban -y

# Create a local config (don't edit the default)
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
sudo nano /etc/fail2ban/jail.local
[sshd]
enabled = true
port = 2222       # match your SSH port
maxretry = 3
bantime = 1h
findtime = 10m
sudo systemctl enable --now fail2ban

# Check ban status
sudo fail2ban-client status sshd

8. Full Hardened Config Example

# /etc/ssh/sshd_config
Port 2222
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
AuthorizedKeysFile .ssh/authorized_keys
MaxAuthTries 3
LoginGraceTime 20
X11Forwarding no
PermitEmptyPasswords no
AllowUsers youruser
# Test config for syntax errors before restarting
sudo sshd -t

# Restart SSH
sudo systemctl restart sshd

Check Who's Trying to Connect

# Failed attempts
sudo journalctl -u sshd | grep "Failed"
sudo grep "Failed password" /var/log/auth.log

# Successful logins
sudo journalctl -u sshd | grep "Accepted"

# Currently banned IPs
sudo fail2ban-client status sshd
