launchd — macOS Task Scheduling

launchd is the macOS system for scheduling tasks. It replaces cron on macOS and handles everything from system daemons to user launch agents. Understanding launchd properly is essential for automating anything on macOS.

launchd vs cron on macOS

cron technically still works on macOS but Apple deprecated it. launchd is the correct approach — it handles sleep/wake cycles, runs missed jobs after wakeup, and integrates with the system properly. Use launchd for any new automation on macOS.

Plist File Locations

LocationRuns asWhen
~/Library/LaunchAgents/Current userWhen user is logged in
/Library/LaunchAgents/Current userWhen any user logs in
/Library/LaunchDaemons/rootSystem boot, no login needed
/System/Library/LaunchDaemons/rootApple system services (don't touch)

Create a Launch Agent

nano ~/Library/LaunchAgents/com.yourname.myscript.plist
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.yourname.myscript</string>

  <key>ProgramArguments</key>
  <array>
    <string>/bin/bash</string>
    <string>/Users/yourname/scripts/myscript.sh</string>
  </array>

  <key>StartCalendarInterval</key>
  <dict>
    <key>Hour</key>
    <integer>9</integer>
    <key>Minute</key>
    <integer>0</integer>
  </dict>

  <key>StandardOutPath</key>
  <string>/tmp/myscript.log</string>

  <key>StandardErrorPath</key>
  <string>/tmp/myscript.error.log</string>
</dict>
</plist>

StartCalendarInterval Examples

<!-- Every day at 9:00 AM -->
<key>StartCalendarInterval</key>
<dict>
  <key>Hour</key><integer>9</integer>
  <key>Minute</key><integer>0</integer>
</dict>

<!-- Every Monday at 8:30 AM (Weekday 1 = Monday) -->
<key>StartCalendarInterval</key>
<dict>
  <key>Weekday</key><integer>1</integer>
  <key>Hour</key><integer>8</integer>
  <key>Minute</key><integer>30</integer>
</dict>

<!-- Every 15 minutes -->
<key>StartInterval</key>
<integer>900</integer>

<!-- Run at login -->
<key>RunAtLoad</key>
<true/>

Load, Unload, and Manage

# Load (activate) a launch agent
launchctl load ~/Library/LaunchAgents/com.yourname.myscript.plist

# Load and start immediately
launchctl load -w ~/Library/LaunchAgents/com.yourname.myscript.plist

# Unload (deactivate)
launchctl unload ~/Library/LaunchAgents/com.yourname.myscript.plist

# Run immediately (for testing)
launchctl start com.yourname.myscript

# Stop
launchctl stop com.yourname.myscript

# Check if loaded
launchctl list | grep yourname

# Check last exit status and last run time
launchctl list com.yourname.myscript

Bootstrap / Bootout (macOS 10.11+)

# Modern way to load (use this on Ventura and later)
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.yourname.myscript.plist

# Modern way to unload
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.yourname.myscript.plist

Run on File Change (Watch a Folder)

<key>WatchPaths</key>
<array>
  <string>/Users/yourname/Desktop/watch-folder</string>
</array>

Validate Your Plist

plutil -lint ~/Library/LaunchAgents/com.yourname.myscript.plist

Always validate before loading — a syntax error in the plist causes silent failure.

View Logs

# System log for launchd errors
log show --predicate 'subsystem == "com.apple.launchd"' --last 1h

# Your script's output (if you set StandardOutPath)
tail -f /tmp/myscript.log
