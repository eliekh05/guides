ZFS on Linux — Basics

ZFS is a combined filesystem and volume manager with built-in RAID, snapshots, compression, and data integrity checking. OpenZFS is the actively maintained open-source implementation used on Linux, FreeBSD, and macOS.

Install ZFS

# Ubuntu (included in linux-image-generic from 20.04)
sudo apt install zfsutils-linux -y

# Fedora
sudo dnf install zfs -y    # requires DKMS kernel module

# Arch
yay -S zfs-dkms zfs-utils

Core Concepts

  • Pool (zpool) — one or more physical disks grouped together
  • Dataset — a filesystem within a pool (like a partition, but more flexible)
  • VDEV — a group of disks with a redundancy configuration (stripe, mirror, RAIDZ)
  • Snapshot — read-only point-in-time copy of a dataset

Create a Pool

# List available disks
lsblk

# Single disk pool (no redundancy)
sudo zpool create mypool /dev/sdb

# Mirror (RAID 1 — survives one disk failure)
sudo zpool create mypool mirror /dev/sdb /dev/sdc

# RAIDZ (RAID 5-like — survives one disk failure, more storage efficient than mirror)
sudo zpool create mypool raidz /dev/sdb /dev/sdc /dev/sdd

# RAIDZ2 (survives two disk failures)
sudo zpool create mypool raidz2 /dev/sdb /dev/sdc /dev/sdd /dev/sde

Pool Status and Health

zpool status           # health of all pools
zpool status mypool    # specific pool
zpool list             # pool sizes and usage

Status shows ONLINE, DEGRADED, FAULTED, or OFFLINE for each device.

Create Datasets

# Datasets mount automatically at /mypool/name
zfs create mypool/data
zfs create mypool/backups
zfs create mypool/media

# List datasets
zfs list

Compression

# Enable LZ4 compression (fast, good ratio — recommended)
zfs set compression=lz4 mypool

# Enable on a specific dataset
zfs set compression=lz4 mypool/data

# Check compression ratio
zfs get compressratio mypool

Snapshots

# Create a snapshot
zfs snapshot mypool/data@2026-06-20

# List snapshots
zfs list -t snapshot

# Roll back to a snapshot (destroys changes since snapshot)
zfs rollback mypool/data@2026-06-20

# Delete a snapshot
zfs destroy mypool/data@2026-06-20

Automatic Snapshots

# Install zfs-auto-snapshot
sudo apt install zfs-auto-snapshot -y

# It creates cron jobs for frequent, hourly, daily, weekly, monthly snapshots
crontab -l | grep zfs

Send and Receive (Replication)

# Send a snapshot to another pool (local backup)
zfs send mypool/data@2026-06-20 | zfs receive backuppool/data

# Send to a remote server
zfs send mypool/data@2026-06-20 | ssh user@backupserver zfs receive backuppool/data

# Incremental send (only changes since last snapshot)
zfs send -i mypool/data@snap1 mypool/data@snap2 | zfs receive backuppool/data

Scrub (Data Integrity Check)

# Start a scrub (checks all data against checksums)
sudo zpool scrub mypool

# Check scrub status
zpool status mypool | grep scrub

# Run scrub monthly via cron
0 2 1 * * zpool scrub mypool

Replace a Failed Disk

# Identify the failed disk from zpool status
zpool status mypool

# Replace it (pool stays online during resilver on mirrors/RAIDZ)
sudo zpool replace mypool /dev/sdb /dev/sde

# Watch resilver progress
zpool status mypool
