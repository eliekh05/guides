GPG — Encrypt Files and Verify Signatures

GPG (GNU Privacy Guard) implements public-key cryptography. You use it to encrypt files so only the intended recipient can read them, sign files to prove they came from you, and verify that software you download hasn't been tampered with.

How It Works

GPG uses a key pair — a public key you share with everyone, and a private key you never share. Someone encrypts a file with your public key. Only your private key can decrypt it. You sign a file with your private key. Anyone with your public key can verify the signature.

Install GPG

# Linux (usually pre-installed)
sudo apt install gnupg -y

# macOS
brew install gnupg

Generate a Key Pair

gpg --full-generate-key

# Choose:
# Key type: RSA and RSA (default)
# Key size: 4096
# Expiry: 1y (rotate annually) or 0 for no expiry
# Enter your name and email
# Set a strong passphrase — this protects your private key

List Your Keys

# List public keys
gpg --list-keys

# List private keys
gpg --list-secret-keys

# Output shows key ID and fingerprint:
# pub   rsa4096 2024-01-01 [SC]
#       AABBCCDD11223344AABBCCDD11223344AABBCCDD
# uid   Your Name

Export and Share Your Public Key

# Export to a file
gpg --armor --export you@example.com > mypubkey.asc

# Upload to a keyserver so others can find you
gpg --keyserver keyserver.ubuntu.com --send-keys YOUR_KEY_ID

# Print fingerprint to verify over another channel
gpg --fingerprint you@example.com

Import Someone Else's Key

# Import from a file
gpg --import theirkey.asc

# Import from a keyserver
gpg --keyserver keyserver.ubuntu.com --recv-keys THEIR_KEY_ID

# Verify the fingerprint matches what they gave you out-of-band
gpg --fingerprint their@email.com

Encrypt a File

# Encrypt for a recipient (they decrypt with their private key)
gpg --encrypt --recipient their@email.com --armor file.txt
# Creates file.txt.asc

# Encrypt for multiple recipients
gpg --encrypt -r alice@example.com -r bob@example.com file.txt

# Encrypt with a passphrase instead of a key (symmetric)
gpg --symmetric file.txt
# Creates file.txt.gpg

Decrypt a File

# Decrypt (GPG finds the right private key automatically)
gpg --decrypt file.txt.asc > file.txt

# Or let GPG write the output file
gpg --output file.txt --decrypt file.txt.asc

Sign a File

# Create a detached signature (separate .sig file)
gpg --detach-sign file.tar.gz
# Creates file.tar.gz.sig

# Create an armored (text) signature
gpg --armor --detach-sign file.tar.gz
# Creates file.tar.gz.asc

# Sign and encrypt in one step
gpg --sign --encrypt --recipient their@email.com file.txt

Verify a Signature

# Verify a detached signature
gpg --verify file.tar.gz.sig file.tar.gz

# Good signature output:
# gpg: Good signature from "Developer Name "

# Bad signature output:
# gpg: BAD signature from ...
# Never trust a file with a bad signature

Verify Downloaded Software

Many projects publish GPG signatures alongside their releases. Here's the pattern:

# Example: verifying a release
# 1. Import the project's signing key
gpg --keyserver keyserver.ubuntu.com --recv-keys PROJECT_KEY_ID

# 2. Download the release and its signature
wget https://project.org/release-1.0.tar.gz
wget https://project.org/release-1.0.tar.gz.sig

# 3. Verify
gpg --verify release-1.0.tar.gz.sig release-1.0.tar.gz

Backup Your Private Key

# Export private key (keep this extremely safe)
gpg --armor --export-secret-keys you@example.com > private-key-backup.asc

# Store encrypted, offline — a USB in a safe, not cloud storage

# Import on a new machine
gpg --import private-key-backup.asc

Revoke a Key

# Generate a revocation certificate when you create the key
# (do this while you still have access)
gpg --gen-revoke you@example.com > revoke.asc

# If your key is compromised, import the revocation
gpg --import revoke.asc

# Upload the revoked key to keyservers
gpg --keyserver keyserver.ubuntu.com --send-keys YOUR_KEY_ID
