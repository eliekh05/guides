Fix Broken sudo on Linux

Accidentally removing your user from the sudo group, editing sudoers incorrectly, or corrupting the sudo binary leaves you locked out of administrative commands. Here is how to recover.

Diagnose the Problem

# Check if your user is in the sudo group
groups $(whoami)

# Check sudoers file syntax
sudo visudo --check

# Test sudo
sudo -l

Fix 1 — Switch to Root (If Root Login Is Available)

su -
# Enter root password
# Add your user back to sudo
usermod -aG sudo yourusername    # Debian/Ubuntu
usermod -aG wheel yourusername   # Fedora/RHEL/Arch
exit

Log out and back in for the group change to take effect.

Fix 2 — Use Another sudo User

If another user on the system has sudo access, log in as them and add your user:

sudo usermod -aG sudo yourusername

Fix 3 — Single User Mode (Recovery Mode)

If no root password and no other sudo user, boot into recovery mode:

Ubuntu/Debian:

  1. Restart → hold Shift to show GRUB menu
  2. Select Advanced options → Recovery mode
  3. Select root — Drop to root shell prompt
  4. Remount filesystem as writable: mount -o remount,rw /
  5. usermod -aG sudo yourusername
  6. reboot

Fedora/RHEL:

  1. Restart → press E at GRUB to edit the boot entry
  2. Find the line starting with linux and append rd.break enforcing=0
  3. Press Ctrl+X to boot
  4. mount -o remount,rw /sysroot
  5. chroot /sysroot
  6. usermod -aG wheel yourusername
  7. exit && reboot

Fix 4 — Corrupted sudoers File

If you broke sudoers with a bad edit (bypassing visudo), fix it in recovery mode:

# In recovery shell with filesystem mounted rw:
cp /etc/sudoers /etc/sudoers.broken
cp /etc/sudoers.d/README /tmp/    # just to verify the directory exists

# Restore from package
dpkg --verify sudo                 # Ubuntu/Debian
rpm -V sudo                        # Fedora/RHEL

# Or restore default sudoers manually
cat > /etc/sudoers << 'SUDOEOF'
Defaults env_reset
Defaults mail_badpass
Defaults secure_path="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"

root ALL=(ALL:ALL) ALL
%sudo ALL=(ALL:ALL) ALL    # Ubuntu/Debian
%wheel ALL=(ALL) ALL       # Fedora/RHEL/Arch

@includedir /etc/sudoers.d
SUDOEOF

chmod 440 /etc/sudoers
chown root:root /etc/sudoers

Fix 5 — Live USB

Boot from a Linux live USB, mount your system partition, and chroot into it:

sudo mount /dev/sda2 /mnt          # replace with your root partition
sudo mount --bind /dev /mnt/dev
sudo mount --bind /proc /mnt/proc
sudo mount --bind /sys /mnt/sys
sudo chroot /mnt

# Now inside your broken system:
usermod -aG sudo yourusername
exit

sudo umount -R /mnt
reboot

Prevent This From Happening Again

  • Always use visudo to edit the sudoers file — it validates syntax before saving
  • Keep the root password set on servers
  • Have at least two admin users on any important system
