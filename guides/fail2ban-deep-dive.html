fail2ban — Intrusion Prevention Deep Dive

fail2ban watches log files for repeated failed authentication attempts and temporarily bans the source IP using firewall rules. It's one of the most effective ways to reduce brute force attacks on public servers without much effort.

Install

sudo apt install fail2ban -y        # Debian/Ubuntu
sudo dnf install fail2ban -y        # Fedora/RHEL

sudo systemctl enable --now fail2ban

How It Works

fail2ban reads a log file, applies a regex filter to find failed authentication lines, counts how many times an IP triggers the filter within a time window, and if it exceeds the threshold it runs an action (usually adding an iptables/nftables DROP rule for that IP).

Config Structure

/etc/fail2ban/
  jail.conf          # defaults — never edit this directly
  jail.d/            # your custom configs go here
  filter.d/          # regex filters for reading logs
  action.d/          # what to do when banning (iptables, email, etc)

Create Your Local Config

sudo nano /etc/fail2ban/jail.d/custom.conf
[DEFAULT]
# Ban for 1 hour
bantime  = 1h

# Look back 10 minutes
findtime = 10m

# Allow 3 failures before banning
maxretry = 3

# Never ban these IPs
ignoreip = 127.0.0.1/8 ::1 192.168.1.0/24

# Email alerts (optional — configure SMTP separately)
# destemail = admin@yourdomain.com
# action = %(action_mwl)s

[sshd]
enabled  = true
port     = ssh
logpath  = %(sshd_log)s
maxretry = 3
bantime  = 2h
sudo systemctl restart fail2ban

Check Status

# List all active jails
sudo fail2ban-client status

# Status of a specific jail — shows banned IPs and counts
sudo fail2ban-client status sshd

# Watch the log live
sudo tail -f /var/log/fail2ban.log

Manually Ban and Unban

# Ban an IP manually
sudo fail2ban-client set sshd banip 203.0.113.99

# Unban an IP
sudo fail2ban-client set sshd unbanip 203.0.113.99

# Unban from all jails at once
sudo fail2ban-client unban 203.0.113.99

Protect Nginx

sudo nano /etc/fail2ban/jail.d/custom.conf
[nginx-http-auth]
enabled  = true
port     = http,https
logpath  = /var/log/nginx/error.log
maxretry = 3

[nginx-limit-req]
enabled  = true
port     = http,https
logpath  = /var/log/nginx/error.log
maxretry = 10
findtime = 1m

[nginx-botsearch]
enabled  = true
port     = http,https
logpath  = /var/log/nginx/access.log
maxretry = 5

Protect Other Services

[postfix]
enabled  = true
port     = smtp,ssmtp
logpath  = %(postfix_log)s

[dovecot]
enabled  = true
port     = pop3,pop3s,imap,imaps
logpath  = %(dovecot_log)s

[wordpress]
enabled  = true
port     = http,https
logpath  = /var/log/nginx/access.log
filter   = wordpress
maxretry = 3

Write a Custom Filter

sudo nano /etc/fail2ban/filter.d/myapp.conf
[Definition]
failregex = ^ .* "POST /login HTTP.*" 401
ignoreregex =
# Test your filter against a log file
sudo fail2ban-regex /var/log/nginx/access.log /etc/fail2ban/filter.d/myapp.conf

Aggressive Bantime for Repeat Offenders

[DEFAULT]
# Ban multiplier — doubles bantime for each subsequent ban
bantime.increment = true
bantime.multiplier = 2
bantime.maxtime   = 1w    # cap at 1 week

With this config, first offence = 1 hour, second = 2 hours, third = 4 hours, eventually capping at 1 week.

Persistent Bans Across Reboots

[DEFAULT]
# Bans survive fail2ban restarts and reboots
dbpurgeage = 1d    # keep ban records for 1 day

View What Got Banned in the Firewall

# iptables
sudo iptables -L f2b-sshd -n --line-numbers

# nftables (newer systems)
sudo nft list table inet f2b-table

fail2ban is Not Enough Alone

fail2ban slows down brute force attacks but isn't a replacement for:

  • SSH key authentication (disables password auth entirely)
  • Changing the SSH port (reduces noise in logs)
  • A strict firewall that only allows needed ports

Use all three together. fail2ban is the last line of defence, not the first.
