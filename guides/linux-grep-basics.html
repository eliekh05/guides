grep — Search Through Files and Output

grep searches for patterns in text. It's one of those commands you'll use every single day once you know it — filtering logs, finding config values, searching code, checking if something is running.

Basic Usage

# Search for a word in a file
grep "error" logfile.txt

# Search in multiple files
grep "error" *.log

# Search recursively in a directory
grep -r "TODO" /home/user/project/

# Case-insensitive search
grep -i "Error" logfile.txt

Most Useful Flags

FlagWhat it does
-iCase insensitive
-rRecursive (search subdirectories)
-nShow line numbers
-lOnly print filenames that match
-cCount matching lines
-vInvert — show lines that do NOT match
-A 3Show 3 lines After each match
-B 3Show 3 lines Before each match
-C 3Show 3 lines Context (before and after)
-wMatch whole words only
-EExtended regex (same as egrep)
-oPrint only the matching part, not the whole line

Context Lines

# Show 3 lines before and after each match — extremely useful in logs
grep -C 3 "connection refused" /var/log/nginx/error.log

# Show what came right after an error
grep -A 5 "FATAL" app.log

Invert Match

# Show all lines that are NOT comments
grep -v "^#" /etc/nginx/nginx.conf

# Show all lines that are not blank and not comments
grep -v "^#" /etc/ssh/sshd_config | grep -v "^$"

Search Recursively in a Project

# Find all files containing a function name
grep -r "def login" /home/user/project/

# Show filenames only
grep -rl "TODO" /home/user/project/

# Exclude a directory
grep -r "error" /var/log/ --exclude-dir=old-logs

# Only search specific file types
grep -r "import" /home/user/project/ --include="*.py"

Regex Patterns

# Match lines starting with a pattern
grep "^ERROR" logfile.txt

# Match lines ending with a pattern
grep "failed$" logfile.txt

# Match any character
grep "er.or" logfile.txt    # matches error, erxor, er or

# Match digits
grep "[0-9]\{3\}" file.txt      # 3 consecutive digits
grep -E "[0-9]{3}" file.txt     # same with extended regex (-E)

# Match an IP address (approximate)
grep -E "[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}" logfile.txt

# Match either of two patterns
grep -E "error|warning" logfile.txt

Grep with Pipes — Where It Shines

# Filter command output
ps aux | grep nginx
docker ps | grep myapp
systemctl list-units | grep failed

# Count how many times something appears
grep -c "404" /var/log/nginx/access.log

# Find which processes are using a port
ss -tlnp | grep :80

# Filter out noise from a log
tail -f /var/log/syslog | grep -v "systemd"

# Chain multiple greps
cat /var/log/auth.log | grep "Failed" | grep "root"

Extract Specific Parts

# Print only the matched portion
grep -o "[0-9]\+\.[0-9]\+\.[0-9]\+\.[0-9]\+" access.log    # extract IPs

# With extended regex
grep -oE "[0-9]{1,3}(\.[0-9]{1,3}){3}" access.log

ripgrep — A Faster Alternative

If you find yourself using grep on large codebases constantly, ripgrep (rg) is 5-10x faster and smarter about ignoring .git and node_modules:

# Install
sudo apt install ripgrep       # Ubuntu/Debian
brew install ripgrep           # macOS

# Same usage as grep, mostly
rg "TODO" /home/user/project/
rg -i "error" logfile.txt
rg -l "pattern" .              # filenames only
