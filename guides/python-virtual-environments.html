Python Virtual Environments

A virtual environment is an isolated Python installation for a project. Each project gets its own packages at its own versions — no conflicts, no system pollution.

Why Use Virtual Environments

  • Project A needs Django 3.2, Project B needs Django 5.0 — both work fine
  • Installing packages does not affect the system Python
  • Easy to reproduce on another machine with requirements.txt
  • Delete the env folder to cleanly uninstall everything

venv — Built-in (Recommended)

# Create a virtual environment called .venv in current folder
python3 -m venv .venv

# Activate it
source .venv/bin/activate        # macOS/Linux
.venv\Scripts\activate           # Windows PowerShell
.venv\Scripts\activate.bat       # Windows CMD

# Your prompt changes to show the active env:
# (.venv) user@host:~/project$

# Deactivate when done
deactivate

Install Packages

# Always activate first, then install
source .venv/bin/activate
pip install requests flask django

# Install from a requirements file
pip install -r requirements.txt

Save and Share Dependencies

# Save current packages to requirements.txt
pip freeze > requirements.txt

# requirements.txt looks like:
# Django==5.0.1
# requests==2.31.0
# gunicorn==21.2.0

# Someone else restores the exact same environment:
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

Add .venv to .gitignore

# .gitignore
.venv/
__pycache__/
*.pyc
.env

Never commit the .venv folder — it is large, platform-specific, and reproducible from requirements.txt.

uv — Fast Modern Alternative

uv is a drop-in replacement for pip and venv, written in Rust — 10-100x faster than pip:

# Install uv
curl -LsSf https://astral.sh/uv/install.sh | sh

# Create and sync environment
uv venv
source .venv/bin/activate
uv pip install requests flask

# Install from requirements.txt
uv pip install -r requirements.txt

# Sync from pyproject.toml (modern projects)
uv sync

pipx — Global CLI Tools

For command-line tools (not library dependencies), use pipx to install them in isolated environments but make them available globally:

# Install pipx
pip install pipx
pipx ensurepath

# Install CLI tools
pipx install black       # code formatter
pipx install httpie      # HTTP client
pipx install poetry      # dependency manager

# Run them anywhere
black myfile.py
http GET https://api.example.com

Useful pip Commands

# List installed packages
pip list

# Show info about a package
pip show django

# Upgrade a package
pip install --upgrade django

# Uninstall a package
pip uninstall requests

# Check for outdated packages
pip list --outdated

VS Code Integration

VS Code automatically detects virtual environments in your workspace. If it does not:

  1. Cmd/Ctrl+Shift+P → Python: Select Interpreter
  2. Choose the interpreter at .venv/bin/python

The terminal in VS Code will automatically activate the venv.
