Understanding PKI and TLS Certificates

Every time you see HTTPS, a certificate is doing the work behind the scenes. Understanding how Public Key Infrastructure (PKI) actually works helps you debug certificate errors, set up your own CA, and make better decisions about trust.

The Core Problem PKI Solves

When you connect to your bank, how does your browser know it's actually your bank and not an attacker intercepting the connection? Anyone can generate a key pair and claim to be anyone. PKI solves this with a chain of trust — a hierarchy of Certificate Authorities (CAs) that vouch for each other.

The Components

TermWhat it is
Private keySecret key the server keeps. Never leaves the server.
Public keyEmbedded in the certificate. Anyone can see it.
Certificate (cert)Contains the public key + identity info + CA signature
CSRCertificate Signing Request — sent to a CA to get a cert issued
CACertificate Authority — a trusted entity that signs certificates
Root CATop of the trust chain. Pre-installed in browsers and OSes.
Intermediate CASigned by Root CA, used to sign end-entity certificates
Chain of trustYour cert → Intermediate CA → Root CA

How TLS Handshake Works

  1. Client connects and says which TLS versions and ciphers it supports
  2. Server sends its certificate (contains public key)
  3. Client verifies the certificate chain up to a trusted Root CA
  4. Client verifies the cert's domain matches the site it's connecting to
  5. They negotiate a shared session key using asymmetric crypto
  6. All further communication is encrypted with that session key (symmetric crypto — faster)

Certificate Fields That Matter

# View a certificate
openssl x509 -in certificate.crt -text -noout

# Key fields:
# Subject: CN=example.com          — who the cert is for
# Issuer: CN=Let's Encrypt...      — who signed it
# Not Before / Not After           — validity period
# Subject Alternative Names        — all domains this cert covers
# Public Key                       — the public key itself

Verify a Certificate Chain

# Check a live site's certificate
openssl s_client -connect example.com:443 -showcerts

# Verify cert against a CA bundle
openssl verify -CAfile /etc/ssl/certs/ca-certificates.crt certificate.crt

# Check expiry date
echo | openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -dates

# Check what domains a cert covers
echo | openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -text | grep -A1 "Subject Alternative"

Create a Private Key and CSR

# Generate a private key
openssl genrsa -out server.key 4096

# Create a CSR to send to a CA
openssl req -new -key server.key -out server.csr
# Fill in: country, state, org, common name (your domain)

# View what's in the CSR
openssl req -text -noout -in server.csr

Self-Signed Certificates

For internal tools, development, or testing — not for public sites:

# Generate key + self-signed cert in one command
openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem -days 365 -nodes \
  -subj "/CN=myapp.internal"

# With Subject Alternative Names (modern browsers require this)
openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem -days 365 -nodes \
  -subj "/CN=myapp.internal" \
  -addext "subjectAltName=DNS:myapp.internal,DNS:localhost,IP:127.0.0.1"

Run Your Own Internal CA

# Create root CA key and cert
openssl genrsa -out rootCA.key 4096
openssl req -x509 -new -nodes -key rootCA.key -sha256 -days 3650 \
  -out rootCA.crt -subj "/CN=My Internal CA"

# Sign a server certificate with your CA
openssl genrsa -out server.key 4096
openssl req -new -key server.key -out server.csr -subj "/CN=myapp.internal"
openssl x509 -req -in server.csr -CA rootCA.crt -CAkey rootCA.key \
  -CAcreateserial -out server.crt -days 365 -sha256

# Install rootCA.crt on client machines so they trust your CA
# Linux: sudo cp rootCA.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates
# macOS: Security → Keychain Access → import + trust the root cert
# Windows: certmgr.msc → Trusted Root Certification Authorities → import

ErrorCauseFix
Certificate expiredPast the Not After dateRenew the certificate

Incomplete chainMissing intermediate certInclude full chain (fullchain.pem)
Self-signedNo CA vouching for itInstall root CA on clients, or use Let's Encrypt
