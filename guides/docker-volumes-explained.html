Docker Volumes — Persistent Data That Survives Container Restarts

Containers are ephemeral — when you remove one, everything inside it is gone. Volumes are how you keep data around. Databases, uploads, config files — anything that needs to persist goes in a volume.

The Three Ways to Store Data

TypeWhat it isUse for
VolumeManaged by Docker, stored in /var/lib/docker/volumesDatabases, persistent app data
Bind mountA folder on your host machineDev work, config files you need to edit
tmpfsRAM only, gone when container stopsSensitive temp data, caches

Named Volumes

# Create a volume
docker volume create mydata

# Use it when running a container
docker run -v mydata:/var/lib/postgresql/data postgres

# List volumes
docker volume ls

# Inspect a volume (see where data actually lives)
docker volume inspect mydata

# Remove a volume (data is gone permanently)
docker volume rm mydata

Volumes in Docker Compose

services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7
    volumes:
      - redisdata:/data

volumes:
  pgdata:
  redisdata:

Compose creates the volumes automatically when you run docker compose up. They persist even when you do docker compose down — use docker compose down -v to also remove them.

Bind Mounts

# Mount your current directory into the container
docker run -v $(pwd):/app node:20 npm start

# Mount a specific folder
docker run -v /home/user/config:/etc/myapp/config myapp

# Read-only bind mount
docker run -v /home/user/config:/etc/myapp/config:ro myapp
services:
  api:
    image: myapi
    volumes:
      - ./src:/app/src        # bind mount — host path:container path
      - appdata:/app/data     # named volume

volumes:
  appdata:

Backup a Volume

# Backup volume data to a tar file
docker run --rm \
  -v mydata:/source \
  -v $(pwd):/backup \
  alpine tar czf /backup/mydata-backup.tar.gz -C /source .

# Restore from backup
docker run --rm \
  -v mydata:/target \
  -v $(pwd):/backup \
  alpine tar xzf /backup/mydata-backup.tar.gz -C /target

Copy Files In and Out

# Copy a file from container to host
docker cp mycontainer:/etc/config.json ./config.json

# Copy a file from host to container
docker cp ./config.json mycontainer:/etc/config.json

Explore Volume Contents

# Spin up a temporary container to browse the volume
docker run --rm -it -v mydata:/data alpine sh
# Now you can ls /data, cat files, etc.

Clean Up Unused Volumes

# Remove all volumes not attached to a container
docker volume prune

# Remove everything unused (containers, images, networks, volumes)
docker system prune --volumes

Volume Permissions

A common headache: the app inside the container runs as a non-root user but the volume is owned by root. Fix it by setting the user in your Dockerfile or compose file:

services:
  app:
    image: myapp
    user: "1000:1000"    # match the UID inside the container
    volumes:
      - appdata:/data
# Or fix ownership from a temporary container
docker run --rm -v mydata:/data alpine chown -R 1000:1000 /data
