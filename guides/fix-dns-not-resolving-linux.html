Fix DNS Not Resolving on Linux

DNS resolution failures cause websites to be unreachable even when the internet connection itself is working. The site loads if you use an IP address but not a domain name.

Confirm It Is a DNS Issue

# Test with IP vs domain
curl -I https://1.1.1.1          # works = internet is fine
curl -I https://google.com       # fails = DNS issue

# Directly test DNS resolution
dig google.com
nslookup google.com
host google.com

# Test against a specific DNS server
dig google.com @8.8.8.8          # test against Google DNS
dig google.com @1.1.1.1          # test against Cloudflare

Check Current DNS Configuration

# Modern systemd systems
resolvectl status

# Legacy
cat /etc/resolv.conf

# Check what is answering DNS queries
systemd-resolve --status | grep "DNS Servers"

Flush DNS Cache

# systemd-resolved
sudo resolvectl flush-caches
sudo systemd-resolve --flush-caches

# nscd (older systems)
sudo systemctl restart nscd

# dnsmasq
sudo systemctl restart dnsmasq

Restart systemd-resolved

sudo systemctl restart systemd-resolved
sudo systemctl status systemd-resolved

Fix Broken /etc/resolv.conf

# Check what resolv.conf points to
ls -la /etc/resolv.conf

# On systems using systemd-resolved, it should be a symlink:
# /etc/resolv.conf -> /run/systemd/resolve/stub-resolv.conf

# If it is a regular file or wrong symlink, fix it:
sudo rm /etc/resolv.conf
sudo ln -s /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf
sudo systemctl restart systemd-resolved

Set a Manual DNS Server

# Via NetworkManager (persists across reboots)
nmcli connection show                          # list connections
nmcli connection modify "CONNECTION-NAME" ipv4.dns "1.1.1.1 8.8.8.8"
nmcli connection modify "CONNECTION-NAME" ipv4.ignore-auto-dns yes
nmcli connection up "CONNECTION-NAME"

# Verify
resolvectl status

Fix DNS on Ubuntu with systemd-resolved

sudo nano /etc/systemd/resolved.conf
[Resolve]
DNS=1.1.1.1 8.8.8.8
FallbackDNS=9.9.9.9
DNSStubListener=yes
sudo systemctl restart systemd-resolved

DNS Works for Some Domains but Not Others

This usually means the DNS server is returning NXDOMAIN for certain domains, or there is a search domain issue.

# Check search domains
cat /etc/resolv.conf | grep search

# Test without search domains
dig google.com.     # note the trailing dot — disables search domain appending

# Check if DNSSEC validation is failing
dig +dnssec google.com
resolvectl query google.com

Fix Docker Breaking Host DNS

Docker can interfere with host DNS by modifying /etc/resolv.conf:

# Check if Docker is the problem
systemctl stop docker
resolvectl flush-caches
# Test DNS — if it works now, Docker was the issue

# Fix — configure Docker to use a specific DNS
sudo nano /etc/docker/daemon.json
{
  "dns": ["1.1.1.1", "8.8.8.8"]
}
sudo systemctl restart docker

VPN Breaking DNS

VPNs often push their own DNS servers which may be slow or broken:

# Check DNS after connecting to VPN
resolvectl status

# If VPN DNS is the problem, either:
# 1. Disconnect the VPN
# 2. Override DNS in your VPN client settings
# 3. Configure split DNS in NetworkManager
