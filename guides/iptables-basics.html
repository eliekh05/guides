iptables Basics — Linux Firewall Rules

iptables is the underlying firewall framework on Linux. Tools like UFW and firewalld write iptables rules for you, but understanding iptables directly lets you handle complex scenarios they can't. On modern systems nftables is replacing iptables, but iptables syntax is still widely used and supported.

How iptables Works

iptables processes packets through tables → chains → rules. Each rule has a match condition and a target (what to do).

TablePurpose
filterDefault. Controls which packets are allowed in/out
natNetwork address translation — port forwarding, masquerade
mangleModify packet headers
ChainWhen it applies
INPUTPackets destined for this machine
OUTPUTPackets originating from this machine
FORWARDPackets routing through this machine
PREROUTINGBefore routing decision (nat table)
POSTROUTINGAfter routing decision (nat table)

View Current Rules

# List all rules with line numbers
sudo iptables -L -n -v --line-numbers

# List a specific chain
sudo iptables -L INPUT -n -v

# List NAT rules
sudo iptables -t nat -L -n -v

Basic Rule Syntax

sudo iptables -[A/I/D] CHAIN -[options] -j TARGET
FlagMeaning
-AAppend rule to end of chain
-IInsert rule at beginning (or specific position)
-DDelete a rule
-pProtocol (tcp, udp, icmp)
--dportDestination port
--sportSource port
-sSource IP/subnet
-dDestination IP/subnet
-iInput interface (eth0, etc)
-oOutput interface
-jJump to target: ACCEPT, DROP, REJECT, LOG

Common Rules

# Allow established connections (essential — add this first)
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Allow loopback
sudo iptables -A INPUT -i lo -j ACCEPT

# Allow SSH
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Allow HTTP and HTTPS
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Allow from specific IP only
sudo iptables -A INPUT -s 192.168.1.100 -p tcp --dport 5432 -j ACCEPT

# Drop everything else
sudo iptables -A INPUT -j DROP

Rate Limiting (Brute Force Protection)

# Limit SSH to 3 connections per minute
sudo iptables -A INPUT -p tcp --dport 22 -m state --state NEW \
  -m limit --limit 3/min --limit-burst 3 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j DROP

Logging

# Log dropped packets (add before a DROP rule)
sudo iptables -A INPUT -j LOG --log-prefix "IPTables-Dropped: " --log-level 4

# View logs
sudo dmesg | grep "IPTables-Dropped"
sudo tail -f /var/log/kern.log | grep IPTables

NAT — Port Forwarding

# Forward external port 8080 to internal port 80
sudo iptables -t nat -A PREROUTING -p tcp --dport 8080 -j REDIRECT --to-port 80

# Forward to another machine
sudo iptables -t nat -A PREROUTING -p tcp --dport 8080 \
  -j DNAT --to-destination 192.168.1.50:80
sudo iptables -A FORWARD -p tcp -d 192.168.1.50 --dport 80 -j ACCEPT

# Masquerade outgoing traffic (for NAT router setup)
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

Delete Rules

# Delete by rule number
sudo iptables -L INPUT --line-numbers
sudo iptables -D INPUT 3    # delete rule 3

# Delete by matching the rule
sudo iptables -D INPUT -p tcp --dport 80 -j ACCEPT

# Flush all rules in a chain
sudo iptables -F INPUT

# Flush everything
sudo iptables -F

Save Rules (Survive Reboot)

# Ubuntu/Debian
sudo apt install iptables-persistent -y
sudo netfilter-persistent save

# Fedora/RHEL
sudo service iptables save

# Manual
sudo iptables-save > /etc/iptables/rules.v4
# Restore with:
sudo iptables-restore < /etc/iptables/rules.v4

Secure Default Policy

# Set default policies — deny everything, then allow what you need
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

# Essential rules to add BEFORE setting DROP policy
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT    # SSH
