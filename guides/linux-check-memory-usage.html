Check Memory Usage on Linux

Memory issues on Linux are often misread — Linux deliberately uses free RAM for disk cache, so "low free memory" is normal and not a problem. Here's how to read memory usage correctly.

The Main Commands

# Human-readable overview
free -h

# Example output:
#               total    used    free  shared  buff/cache  available
# Mem:           15Gi    4.2Gi   8.1Gi   312Mi    3.1Gi      10Gi
# Swap:          2.0Gi      0B   2.0Gi

The column that matters is available — not free. Available is what applications can actually use. Free means truly unused RAM.

What the Columns Mean

ColumnMeaning
totalTotal physical RAM
usedRAM in use by processes
freeCompletely unused RAM — usually low and that's fine
sharedRAM used by tmpfs (shared memory between processes)
buff/cacheRAM used as disk cache — Linux reclaims this instantly if an app needs it
availableEstimate of RAM available for new applications — the number to watch

Find What's Using Memory

# Interactive — sort by memory with M in top, or F6 in htop
top
htop

# Static snapshot sorted by memory
ps aux --sort=-%mem | head -15

# Show RSS (actual RAM) and VSZ (virtual) for each process
ps aux --sort=-%mem | awk '{print $4, $6, $11}' | head -15

/proc/meminfo — Detailed Breakdown

cat /proc/meminfo

# Key fields:
# MemTotal        — total RAM
# MemFree         — unused RAM
# MemAvailable    — available for applications
# Buffers         — raw disk block cache
# Cached          — page cache
# SwapTotal       — total swap space
# SwapFree        — unused swap

Check Swap Usage

# Overview
swapon --show
free -h

# Detailed swap usage per process
cat /proc/*/status 2>/dev/null | grep -E "Name|VmSwap" | paste - - | sort -k4 -rh | head -10

Heavy swap usage means you're genuinely out of RAM. Light swap usage is normal.

Find Memory Leaks

# Watch a process's memory over time
watch -n 2 'ps -p PID -o pid,rss,vsz,cmd'

# Monitor all processes and log anything over 1GB
ps aux --sort=-%mem | awk '$6 > 1000000 {print $0}'

Drop the Cache (Testing Only)

Sometimes useful to free cache memory for benchmarking — not needed in normal use:

sudo sync
echo 3 | sudo tee /proc/sys/vm/drop_caches

Get a Memory Report

# smem shows per-process proportional set size (more accurate than RSS)
sudo apt install smem
smem -r | head -15

# vmstat — shows memory, swap, and I/O together
vmstat 1 5    # 1-second intervals, 5 times

You're Actually Low on Memory When

  • The available column in free -h is near zero
  • Swap usage is high and increasing
  • The system feels sluggish and disk activity is constant (thrashing)
  • The OOM killer starts terminating processes — check with dmesg | grep -i "killed process"
