Fix GRUB Bootloader

A broken GRUB leaves you with a system that will not boot — either a blank screen, a GRUB rescue prompt, or an error message. Here is how to diagnose and fix each case.

Identify Your Situation

  • GRUB rescue> prompt — GRUB loads but cannot find its configuration or modules
  • error: no such partition — the root partition GRUB expects is missing or changed
  • Blank screen after POST — GRUB itself is not loading (MBR/EFI issue)
  • GRUB menu appears but OS fails to boot — GRUB is fine, issue is with the kernel or initramfs

Boot from Live USB First

For most fixes, boot a Linux live USB (Ubuntu, Fedora, or any distro) and chroot into your broken system.

Chroot Into Your System

# Find your partitions
lsblk
fdisk -l

# Mount root partition (replace /dev/sda2 with yours)
sudo mount /dev/sda2 /mnt

# If you have a separate /boot partition
sudo mount /dev/sda1 /mnt/boot

# If using EFI
sudo mount /dev/sda1 /mnt/boot/efi

# Bind system directories
sudo mount --bind /dev /mnt/dev
sudo mount --bind /proc /mnt/proc
sudo mount --bind /sys /mnt/sys
sudo mount --bind /run /mnt/run

# Chroot
sudo chroot /mnt

Reinstall GRUB (Most Common Fix)

# Inside chroot — BIOS/MBR systems
grub-install /dev/sda     # install to disk, not partition
update-grub

# UEFI systems
grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=ubuntu
update-grub
# Fedora/RHEL (inside chroot)
grub2-install /dev/sda
grub2-mkconfig -o /boot/grub2/grub.cfg

# UEFI Fedora
grub2-install --target=x86_64-efi --efi-directory=/boot/efi
grub2-mkconfig -o /boot/efi/EFI/fedora/grub.cfg

Fix from GRUB Rescue Prompt

# List available partitions
grub rescue> ls

# Try each partition to find your root
grub rescue> ls (hd0,1)/
grub rescue> ls (hd0,2)/     # look for /etc, /home etc

# Once found, set root and prefix
grub rescue> set root=(hd0,2)
grub rescue> set prefix=(hd0,2)/boot/grub
grub rescue> insmod normal
grub rescue> normal

This boots into your system temporarily. Then reinstall GRUB properly from there.

Regenerate GRUB Config

# Regenerate without reinstalling (if GRUB loads but menu is wrong)
sudo update-grub           # Ubuntu/Debian
sudo grub2-mkconfig -o /boot/grub2/grub.cfg    # Fedora/RHEL
sudo grub-mkconfig -o /boot/grub/grub.cfg      # Arch

Fix GRUB After Windows Update Overwrites Boot Sector

Windows updates sometimes overwrite the EFI boot entry, making Windows boot instead of GRUB. Fix from a live USB:

# After chroot (see above)
# Reinstall GRUB to EFI
grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=ubuntu --recheck
update-grub

# Exit chroot and reboot
exit
sudo umount -R /mnt
reboot

Fix Missing initramfs

# Inside chroot — rebuild initramfs
update-initramfs -u -k all     # Ubuntu/Debian
dracut --force --regenerate-all # Fedora/RHEL
mkinitcpio -P                   # Arch

Verify UEFI Boot Entries

# List EFI boot entries
sudo efibootmgr -v

# Add a missing GRUB entry
sudo efibootmgr --create --disk /dev/sda --part 1 --label "Ubuntu" --loader /EFI/ubuntu/grubx64.efi

# Set boot order (put GRUB first)
sudo efibootmgr --bootorder 0001,0002,0000
