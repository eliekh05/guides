UFW — Firewall Basics for Linux

UFW (Uncomplicated Firewall) is the straightforward way to manage firewall rules on Ubuntu and Debian. It sits on top of iptables and translates simple commands into the right rules so you don't have to write iptables syntax directly.

Install and Enable

sudo apt install ufw -y

# Set default policies first — deny all incoming, allow all outgoing
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Enable the firewall
sudo ufw enable

# Check status
sudo ufw status verbose

Always allow SSH before enabling UFW on a remote server — otherwise you lock yourself out.

Allow Services

# By service name (UFW knows common services)
sudo ufw allow OpenSSH
sudo ufw allow http
sudo ufw allow https

# By port number
sudo ufw allow 22
sudo ufw allow 80
sudo ufw allow 443

# By port and protocol
sudo ufw allow 51820/udp    # WireGuard
sudo ufw allow 3000/tcp     # custom app

# Port range
sudo ufw allow 6000:6007/tcp

Allow from Specific IPs

# Allow SSH only from your home IP
sudo ufw allow from 203.0.113.10 to any port 22

# Allow anything from a trusted subnet
sudo ufw allow from 192.168.1.0/24

# Allow a specific IP to a specific port
sudo ufw allow from 10.0.0.5 to any port 5432    # Postgres from one host only

Deny and Delete Rules

# Deny a port
sudo ufw deny 8080

# Delete a rule by re-typing it with delete
sudo ufw delete allow 80
sudo ufw delete allow from 203.0.113.10 to any port 22

# Delete by rule number
sudo ufw status numbered
sudo ufw delete 3

Application Profiles

# List available app profiles
sudo ufw app list

# Allow by app profile
sudo ufw allow "Nginx Full"      # opens 80 and 443
sudo ufw allow "Nginx HTTPS"     # opens 443 only

# See what a profile includes
sudo ufw app info "Nginx Full"

Limit Connections (Basic Brute Force Protection)

# Rate-limit SSH — blocks IPs with 6+ connections in 30 seconds
sudo ufw limit ssh

# Same for a custom port
sudo ufw limit 2222/tcp

Logging

# Enable logging
sudo ufw logging on
sudo ufw logging medium    # low, medium, high, full

# View firewall logs
sudo tail -f /var/log/ufw.log

Reset Everything

# Wipe all rules and start over
sudo ufw reset

Full Example — Secure Web Server

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp          # SSH
sudo ufw allow 80/tcp          # HTTP
sudo ufw allow 443/tcp         # HTTPS
sudo ufw limit 22/tcp          # rate-limit SSH
sudo ufw enable
sudo ufw status verbose

UFW and Docker

Docker bypasses UFW by writing its own iptables rules directly. A port published with -p 8080:80 will be exposed publicly even if UFW blocks port 8080. To fix this, bind Docker ports to localhost only:

# Bind to localhost — not exposed externally
docker run -p 127.0.0.1:8080:80 nginx

# Then proxy through Nginx which UFW does control
